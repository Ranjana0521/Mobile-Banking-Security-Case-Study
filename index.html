🎓 College Viva Defense & Security Notes

Core rationale and answers for external examiners and academic evaluators.

Q1: How does this project prevent SharkBot/TeaBot Android keyloggers?
Through the Fisher-Yates Scrambled Numeric Keypad. Traditional touch loggers record exact screen coordinates (X, Y). By dynamically randomizing button positions upon every session and key press, recorded touch coordinates correspond to arbitrary non-correlated digits.
Q2: Why use AES-256-GCM instead of AES-CBC at rest?
AES-CBC provides confidentiality but no integrity verification (vulnerable to padding oracle and bit-flipping attacks). AES-GCM is an AEAD (Authenticated Encryption with Associated Data) cipher that produces a 128-bit GHASH authentication tag. Any 1-bit alteration immediately raises an InvalidTag exception.
Q3: How does transaction-bound HMAC-SHA256 prevent replay attacks?
Unlike static SMS OTPs, the OTP hash is computed over (user_id, recipient, amount, timestamp_window) with a 180s TTL. If an attacker intercepts the OTP and attempts to use it for a different amount or recipient, verification fails cryptographically.
Q4: Why Scrypt KDF instead of plain SHA-256 for passwords?
Plain SHA-256 takes sub-microsecond time on modern GPUs (billions of guesses per second). Scrypt is memory-hard ($N=16,384, r=8, p=1$), demanding ~16MB of RAM per attempt, which paralyzes parallel ASIC and GPU brute-force attacks.
